### 1.4 Why this is not auto-safe

- **Policy.** Deny rule `*n8nio/n8n*` is `max: patch`: a minor is PLAN lane by
  design, attended, because the tag itself cannot say which channel it is on.
- **23 migrations run on first boot, and 5 are irreversible.** Derived 2026-11-19 from the
  upstream directory listings (GitHub contents API) at `n8n@2.46.6` vs `n8n@2.48.5`
  (`packages/@n8n/db/src/migrations/{common,sqlite}`; the SQLite list is all of
  `common/` plus `sqlite/`, a same-name `sqlite/` file shadowing the common one,
  ordered by filename timestamp: `packages/@n8n/db/scripts/generate-migration-index.mjs`).
  23 new files in `common/` (the 21 of the earlier 2.47.7 analysis plus `AddDescriptionToAppVersion1793691670599` and
  `AddContentHashToAgentChatAttachments1794216623022`, both REVERSIBLE additive `ALTER TABLE ... ADD COLUMN`), the same 4
  shadowed by SQLite variants and no new SQLite file, so 23 for
  this instance: 322 -> **345**, newest `AddContentHashToAgentChatAttachments1794216623022`.
  Five implement `IrreversibleMigration` (no `down()`):

  | Migration | What `up()` does | Rows it can touch here (measured) |
  |---|---|---|
  | `BackfillAgentDraftVersions` | inserts `agent_history` rows for project agents | `agents` = 0 |
  | `StoreAgentMemoryEmbeddingsAsBinary` | DROPs and re-adds `agents_memory_entries.embedding` ("Existing embeddings are dropped, not converted") | `agents_memory_entries` = 0 |
  | `ResetAgentPlansForJobStatus` | DELETEs `agent_plan` / `agent_plan_history` rows with `formatVersion < 2` | `agent_plan` = 0, `agent_plan_history` = 0 |
  | `MoveAgentSkillsToProjects` | recreates the `skill` table with foreign keys disabled | `skill` = 0, `skill_version` = 0 |
  | `RemovePublicAppVisibility` | recreates the `app` table with foreign keys disabled | `app` = 0, `app_version` = 0 |

  Also `DropInstanceAiIterationLogs` drops a table (0 rows) and
  `AddExecutionEntityWorkflowIdIndex` builds an index on `execution_entity`
  (0 rows, so it is instant). Nothing destroys data this instance holds, but the
  schema cannot be walked back, so **rollback is restore-from-backup**.
- **Release notes.** The GitHub release bodies for `n8n@2.47.0 .. 2.47.7` and `n8n@2.48.0 .. 2.48.5`
  contain no entry marked BREAKING (case-insensitive count 0 in each, re-read 2026-11-19) and removes no
  env var this HelmRelease sets. Runtime Node moves 26.12.1 -> 26.13.0
  (`docker/images/n8n/Dockerfile` `ARG NODE_VERSION`; entrypoint and `USER node`
  unchanged). Late patches touch stored data and credential handling and are the reason the
  operator opens Credentials once (V9): 2.47.6/2.48.3 "Read legacy-format data with the
  instance key when the stored key differs" (#43725), 2.47.7/2.48.4 "Stop redacting
  executions that use global credentials" (#43776), and 2.48.5 "Treat instance owners and
  admins as team project members in credential checks" (#44183). 2.48.5 also gives FRESH
  installs a random instance ID (#44276; not applicable, this is an upgrade).
- **Helm must not roll back mid-migration.** With `retries: 3` a failed or
  timed-out upgrade makes Helm redeploy 2.46.6 over a partly migrated database,
  and `flux suspend` does not cancel an action in flight. The two clocks are
  already wide (40 m Helm deadline, 1800 s startupProbe, both live and guarded
  by premises). This plan additionally sets `retries: 0` and
  `cleanupOnFail: false` for the window, so a failure ends in `UpgradeFailed`
  with no rollback leg, and restores both in section 3.5.

## 5) Rollback

**A bare `git revert` is NOT a rollback**: it redeploys 2.46.6 against a
database 2.48.5 has migrated (5 migrations have no `down()`). Order is
mandatory: freeze Flux, wait until helm-controller is idle, empty the volume of
pods, restore data, THEN land git, THEN resume. This procedure is the
predecessor plan's (reviewed 2026-11-08); it was not exercised on 2026-11-09
because that run succeeded, and this planner could not exercise it either.

```bash
cd /Users/mu/code/cberg-home-nextgen
# R1 FIRST, always
flux suspend helmrelease n8n -n home-automation
# R1b WAIT FOR TERMINAL (flux suspend does not cancel a Helm action in flight). Cap 45 min.
#     Save this block to a file and run it with `bash <file>` so the STOP really stops.
NS=home-automation; OKN=0; SIGP=""; T=0
for i in $(seq 1 270); do
  R=$(kubectl get helmrelease n8n -n $NS -o jsonpath='{.status.conditions[?(@.type=="Ready")].status}/{.status.conditions[?(@.type=="Ready")].reason}' 2>/dev/null)
  ROWS=$(kubectl get secret -n $NS -l owner=helm,name=n8n --no-headers -o custom-columns=V:.metadata.labels.version,S:.metadata.labels.status 2>/dev/null)
  NR=$(printf '%s\n' "$ROWS" | grep -c '[0-9]')
  P=$(printf '%s\n' "$ROWS" | grep -c -e pending-upgrade -e pending-rollback)
  TOP=$(printf '%s\n' "$ROWS" | awk '{print $1}' | sort -n | tail -1)
  SIG="$(kubectl get helmrelease n8n -n $NS -o jsonpath='{.metadata.generation}/{.status.lastReleaseRevision}' 2>/dev/null)/$TOP"
  if printf '%s' "$R" | grep -Eq '^(True|False)/.+' && [ "$NR" -ge 1 ] && [ "$P" -eq 0 ] && [ -n "$TOP" ]; then
    if [ "$SIG" = "$SIGP" ]; then OKN=$((OKN+1)); else OKN=1; fi
    SIGP="$SIG"
  else
    OKN=0; SIGP=""
  fi
  [ "$OKN" -ge 7 ] && { T=1; break; }
  sleep 10
done
echo "ready=$R rows=$NR pending=$P newest=$TOP stable_polls=$OKN terminal=$T"
[ "$T" -eq 1 ] || { echo "STOP: helm-controller not terminal - do NOT continue to R2"; exit 1; }
```
PASS: `terminal=1` (7 unchanged polls, about 60 s). Today the release secrets
are v66 `superseded` and v67 `deployed`. Only if the run printed `STOP` after
the cap: `kubectl rollout restart deploy/helm-controller -n flux-system`, then
`helm history n8n -n home-automation`; if the newest revision is
`pending-upgrade`, delete exactly that revision's secret so the previous
`deployed` revision is current again, then re-run the block. Attended operator
decision; do not script it.
