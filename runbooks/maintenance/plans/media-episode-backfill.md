## Findings from the 2026-08-15 execution attempt — still authoritative

### P1 — WONTFIX. The fanart cannot be written; the upstream has no image.

The 4 movie folders missing `fanart.jpg` are exactly the 4 carrying an orphan
`movie.nfo`, and Jellyfin reports exactly `with_backdrop_image: 546/550` — one
cluster, three counters. All 4 already carry a TMDb id, so there is no matching risk;
queried directly against `/movie/{id}/images` and `/movie/{id}`, every one returns
`backdrop_path: None` and **0 backdrops across all languages** (1 poster each).
`sidecar.py` guards the write with `if item.get("backdrop_path"):`
(`scripts-configmap.yaml:811`), so it would write nothing.

**`fanart_pct` is 99.2% against a ≥90% floor — this was never a compliance failure.**
Recorded as *best available* per the SOP's repair-pass rule. Synthesising artwork was
considered and **declined by the operator on 2026-08-15**. Do not treat 550/550 as a
target in any stage.

### P1's `movie.nfo` deletion — SUPERSEDED. Do not do it.

The orphan `movie.nfo` is the *richer* file (director, rating, runtime, genre,
country, studio, IMDb id, stream details) versus the minimal 5-field `<folder>.nfo`;
it is regenerated by the servers within hours of any FullRefresh; and the weekly
`media-cleanup-nfos` CronJob (Sun 04:30) already performs exactly this deletion.

### The `sidecar.py` unlink trap — the reason stage 1 exists

`sidecar.py` unlinks **every** `.nfo` in the target folder before writing
(`scripts-configmap.yaml:805`). Run per show with `ITEM_KIND=show`, as the original
plan specified, it would have deleted each show's `tvshow.nfo` and rewritten it from
a fresh TMDb match — taking `series_compliance_pct` off 100.0 while writing **zero**
episode NFOs. `episode_nfo_pct` counts a `.nfo` beside each *episode file*, and no
per-episode writer exists anywhere in `library-tools`. **`sidecar.py` must never be
used for episode work.**

### Two shows hit documented TMDb ladder traps

One folder name is a de-umlauted German title; one is concatenated without separators.
Both return nothing when queried as their folder name and need a hand-supplied
`TMDB_ID`/`TMDB_QUERY`. They are run **last** in stage 3, after the tool is proven.

## DONE 2026-08-15 — the one change that was executed (not superseded)

`REFRESH_SKIP_ART_ONLY=1` (new, default on) in `per_item_refresh.py` +
`per-item-refresh-cronjob.yaml`. `media-per-item-refresh` had been re-detecting the 4
art-only items every 6 h and firing a Jellyfin `FullRefresh` at each one forever; each
FullRefresh rewrites `movie.nfo` on the share, so it was continuously regenerating the
sidecars that `media-cleanup-nfos` deletes weekly — the two CronJobs were fighting
indefinitely. Items whose *only* missing field is the backdrop/art image are now
skipped on both the Plex (`art`) and Jellyfin (`backdrop`) paths; items missing
`overview`/`summary` or the primary/thumb poster still refresh. The gap stays visible
(`media-metadata-coverage` still reports `backdrop_pct`); both Jobs log a
`skipped_art_only` count. Set the env to `"0"` to restore the old behaviour, or revert
the introducing commit — no file writes, so there is nothing on the share to undo.
